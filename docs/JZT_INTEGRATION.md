## 状态与实施边界

本页按《九州通API信息整理 (1).xlsx》（用户提供，2026-10-08）整理。来源是 2024 年历史设计资料，**不是九州通已确认的现行开放接口规范**。下表地址仅供向九州通核对，HTTP 方法、认证、签名、报文包裹层级、数据类型、返回结构、测试及生产环境均待书面确认。不得据此直接接入生产。字段原文、大小写、必填性和规则保存在 [字段字典 CSV](JZT_FIELD_DICTIONARY.csv)；字段计数包括查询参数与返回字段。

现有代码只实现适配器中立的事务出站箱（`gsp_integration_outbox`、幂等、并发认领、退避重试、死信与受审计的人工重放）。九州通网络客户端、认证、映射、入站结果查询和正式对账仍未实现。接口适配器不得直接写 `stock` 或 `gsp_batch_stock`；外部结果先保留原始报文，再由应用服务校验单据、行号、批号、数量和质量状态并决定受控业务转换。

## 内部业务与接口映射

| 接口 | 本系统建议触发或处理点 | 关键关联与控制 |
|---|---|---|
| JZT-01 物料主数据 | 药品主数据经质量批准后进入待发送队列 | `Goods_No`、`Goods_Id`、`LIUS_NO`；先核准编码及单位映射 |
| JZT-02 客户及供应商 | 交易方资质与地址资料经独立批准后 | `Ssa_No`、`Ssa_Sign`（历史值 1 供应商、2 客户）；地址及联系人不能沿用原设计的 `-` 占位值而不核实 |
| JZT-03 采购入库计划 | 经批准的采购入库计划按双方约定下发 | `businessbill_no` 与原始行号；`Storage_Quantity` 在资料中标为非必填，业务上仍需确认缺省含义 |
| JZT-04 采购退货出库计划 | 购进退出经质量批准并满足发运条件后 | `Biz_Bill_No`、行号、供应商、批次及出库方式；避免与实际发运扣减重复 |
| JZT-05 销售出库计划 | 销售审核、购货方资质及库存质量检查通过后 | 单据、行号、收货地址及批次约束；计划下发不代表已出库 |
| JZT-06 销售退货入库计划 | 关联原销售出库及隔离收货流程后 | 单据、行号、原出库引用；结果返回前不自动转为可销售库存 |
| JZT-07/08/09/10 出入库结果查询 | 按单据或时间窗口轮询，原始响应入库后逐行对账 | `Biz_Bill_No`、`Bill_Hdr_Id`、`Bill_Dtl_Id`、`Bill_Dtl_Id_Old`；批号、数量、效期、验收结论分别核验 |
| JZT-11 运输记录查询 | 发运后按单据或时间窗口读取运输、签收和温控记录 | 时间窗口、`begin_index`、`page_size`；分页完整性、重复和迟到记录处理 |

以上触发点为**待业务评审的设计建议**，不是历史资料已经证明的接口行为。现有 `SHIPMENT_CONFIRMED` 等内部出站事件也不能直接等同于 JZT-05 的“计划下发”；需要在适配层定义事件到计划、结果的状态关联。库存快照、盘点、召回、不合格品及追溯平台上传等现有候选消息，附件未给出对应九州通接口，不得按这 11 个地址臆造外部调用。

## 公共标识与返回码

- `Operator_Id/operator_id`、`Con_Id/con_id`、`Ldc_Id/ldc_id` 按环境配置，由九州通分配，不写死在代码或文档示例中。
- 主数据 `LIUS_NO` 由调用方生成且唯一；单据 `Businessbill_No/Biz_Bill_No` 关联本方业务主键；`Bill_Dtl_Id_Old` 用于原始行号回配；九州通 `Bill_Hdr_Id/Bill_Dtl_Id` 留存作对账和幂等参考。唯一性范围、长度、重发规则待确认。
- 历史资料仅明确：`S/0` 正常、`F/1000` 失败、`F/2000` 权限问题。保留原始错误内容；其他状态和“接收成功是否代表处理完成”待确认。
- `Goods_No`、包装单位、批号、生产日期、效期与质量状态在下发和结果之间逐项核对；异常不得自动入可用库存或自动完成发运。

## 请九州通书面确认

1. 11 类接口是否仍有效；每一接口的生产/测试域名、路径、HTTP 方法、请求体示例、包裹层级与响应示例。
2. 认证及签名算法、凭据和环境隔离、IP 白名单、TLS、时间戳、防重放、密钥轮换、调用权限。
3. 字段类型、长度、日期时区、编码、大小写、空值及必填性；商品类型、业务类型、质量结论、温控等全部码表；原设计中的固定值是否仍适用。
4. 单据推送确认与最终作业结果的状态机；分页和增量游标；时钟边界、延迟、补录、撤销、部分成功与多批次/多行回传。
5. 幂等键和有效期、超时后查询规则、限流与重试、错误码全集、失败补偿和日终对账；历史重传如何防止重复记账。
6. 责任边界、联调账号/样本、测试数据、实施周期、验收标准、正式变更通知及是否单独报价。

取得确认版协议后，再设计映射和传输实现，并以重复、乱序、部分成功、批号不符、质量锁定、断网重放及对账差异作为联调/验证用例。
